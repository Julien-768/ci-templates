# 🛠️ GitLab CI/CD Pipeline Template Usage Guide

This guide explains how to use the shared GitLab CI templates for formatting, documentation, and release automation in your PlatformIO C++ project.

---

## 📦 Included Templates

The `.gitlab-ci.yml` includes external reusable jobs from the `iphc/ci-templates` repository:

```yaml
include:
  - project: 'iphc/ci-templates'
    file: '/ci-templates/clang.gitlab-ci.yml'
    ref: 'e8300f4db2e7170bab33e09ec323d3b8ee85364d'

  - project: 'iphc/ci-templates'
    file: '/ci-templates/doxygen.gitlab-ci.yml'
    ref: 'e8300f4db2e7170bab33e09ec323d3b8ee85364d'

  - project: 'iphc/ci-templates'
    file: '/ci-templates/release.gitlab-ci.yml'
    ref: 'e8300f4db2e7170bab33e09ec323d3b8ee85364d'
```

---

## 🔧 Required Variables

Define the following variables in your `.gitlab-ci.yml`:

```yaml
variables:
  CLANG_FORMAT_FILE: .clang-format
  CLANG_PATH: "src include"
  DOXYFILE_PATH: "src include"
  FILES_TO_PACKAGE: "src include lib platformio.ini README.md CHANGELOG.md"
```

Additionally, add this variable in **GitLab > Settings > CI/CD > Variables** (🔐 **Protected**):

| Key             | Description                     |
|----------------|---------------------------------|
| CI_PUSH_TOKEN  | GitLab personal access token with `api` and `write_repository` scope |

---

## 🚦 Pipeline Stages

```yaml
stages:
  - format       # runs clang-format on your sources
  - pages        # generates documentation with Doxygen
  - release      # handles version bump, tag, archive & GitLab release
```

---

## 🚀 Release Jobs

### `release`

This job does the following:

1. Installs `standard-version` and bumps the version in `package.json`
2. Creates a Git tag (e.g., `v0.1.0`) and generates a changelog
3. Archives the source code into a ZIP file
4. Pushes the tag and commit to GitLab

It only runs on the `main` branch when a commit is pushed (excluding `chore(release):` commits).

### `gitlab_release`

This job runs right after `release` and creates a GitLab Release using the [release-cli](https://docs.gitlab.com/ee/user/project/releases/#using-the-release-cli).

It publishes the ZIP artifact generated by `release`.

---

## ✅ Example Commit to Trigger Release

Only the following commit types will trigger the pipeline:

```bash
git commit -m "feat: add new sensor support"
git push origin main
```

Avoid commits starting with `chore(release):` manually — this is generated by `standard-version`.

---

## 📁 Generated Output

- `CHANGELOG.md`: Updated by `standard-version`
- `vX.Y.Z` tag: Created automatically
- `release-vX.Y.Z.zip`: ZIP archive of source
- GitLab Release: Created with description and download link

---

## 🔐 Notes

- Ensure your `CI_PUSH_TOKEN` has proper permissions.
- Do not trigger release commits manually — let the CI handle them.
